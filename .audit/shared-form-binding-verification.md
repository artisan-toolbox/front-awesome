# Shared form binding, state models, and compound documentation

The goal is consistent, maintainable Web Awesome Vue components with two-way form values, useful validation, accurate types, and live documentation that demonstrates the actual public APIs.

## Public behavior

All 18 primary data-entry wrappers support the shared bridge. Core covers Input, Checkbox, Switch, RadioGroup, ColorPicker, KnownDate, NumberInput, OtpInput, Rating, Select, Slider, TagInput, Textarea, and TimeInput. Licensed Pro adds Combobox, DateInput, DatePicker, and FileInput. Grouping containers bind their children rather than inventing a combined value.

A control has one primary owner, either default v-model or an existing Inertia form field. The new field spelling and compatible field-name alias address existing dotted object and array leaves. Conflicting aliases, competing native current values, unsupported modifiers, missing fields, unsafe paths and incompatible value domains are rejected. Input retains its existing required binding; other controls remain usable without a binding.

Server errors remain application-owned. All controls show escaped form.errors[field] messages and danger paint, preserving ordinary hints for restoration. The failed input accepts a boolean, string, or string list. Manual false cannot suppress an Inertia error. Vue treats a bare failed and an empty-string Boolean prop as true, so false or an empty array clears manual failure. Error presentation does not impose native custom validity or clear errors while typing.

The semantic registry contains 62 ports across 38 components, comprising 17 generated primary ports and 45 named state ports. Input supplies the eighteenth primary model separately. Named ports cover genuine mutable state, including Pagination page, TabGroup/Stepper active, overlay open, Page navOpen, DataGrid state and media state. Native read-only observations remain outputs. The catalog's named model reference is checked against the installed definitions.

Setter and native committed domains remain distinct. Rich objects reach native setters without bridge cloning. Mutable arrays, nested records, File arrays, Date and FormData contents are compared through shared snapshots; unchanged values are not replayed on unrelated updates. A same-reference change requests the native public update after its setter where needed. Bound null selection clears current state without changing its reset default. Native resets and prevented resets retain their original behavior.

## Structural decisions and regressions

The generator owns types, explicit SFCs, semantic definitions and compile fixtures. It now runs the actual Vue macro compiler in addition to vue-tsc. Required macro annotations do not bypass the static public contracts. Positive and negative fixtures cover optional native inputs, ownership conflicts, field compatibility, nullable selections and rich state.

Rating and DatePicker have no hint slot. A stable neutral fa-form-field-frame presentation element preserves the actual host, value, focus, event listeners and public $el when validation is activated later. Its inactive display:contents mode omits group semantics. This intentionally changes the literal outer DOM for those two wrappers. Native classes and methods still target the host, and native or Vue-projected slot names also reach the frame. A dedicated element avoids collisions with application selectors for generic spans.

Independent browser review reproduced and verified corrections for dynamic frame replacement and stale in-place TagInput values. Full upstream parity also exposed a missing frame slot and the generic-span selector collision. The wrapper runner adapts only the raw DOM query in Rating example 11 for the documented transparent presentation boundary; the native script remains unchanged and all computed-style and bounds checks remain active. Shared projected slot rendering now updates reactive content while preserving existing native hosts and state.

## Documentation and authoring

The catalog retains all 90 public exports in 80 owning scenarios. Nine compound families share complete examples while retaining individual entries and historical anchors. Seven supplemental Icon and form-binding examples bring the total to 87 shared DemoFrames. Source synchronization follows actual mounted partials, validates owner imports and exact helper filenames, and rejects duplicate or orphan demos.

Forms owns the former Input guide and its historical fragments. Both old route prefixes redirect without replacing incoming hashes. The guide demonstrates local models, nested Inertia fields, collections/files, shared dates, server errors, manual validation and custom public bridge reuse. Icon demonstrates reader-started rendering, transformations, error and retry with exact source. Local preview grids use container queries, so compact resizing changes their actual layout. The shared heading rule also accounts for anchored h4 subsections beneath the sticky header.

Calendar value and viewport are separate upstream state. The guide uses the public goToDate method after selected-date updates so its programmatic actions reveal the corresponding month without making keyboard focus select a date.

## Compatibility and environmental limits

These remain source-preview APIs, not newly published stable exports. Core and Pro imports stay separate. Pro was tested with a real licensed Web Awesome 3.14.0 installation; the wrapper supplies no license. Vue 3.5.45, Inertia Vue 3.11.0, Vite Plus 1.4.0 and Playwright 1.65.0 were inspected in the consuming application.

Native FormData behavior remains upstream behavior. DatePicker contributes no native form entry, a cleared Core Select is omitted, and Pro Combobox submits an empty string. Some upstream controls do not forward every host ARIA error relationship to their internal focused element. No private shadow mutation was introduced. Video playback remains subject to browser autoplay policy, and its native public play method does not return a rejection promise.

Rendering all upstream examples does not prove every possible interaction sequence or browser environment. The maintained suites identify actual keyboard, pointer, lifecycle, reset, rich-value, error and pixel checks. Physical SMS delivery, external services, fullscreen/picture-in-picture permissions and hardware integrations are not claimed as production verification. Sign-in browser requests are intercepted and never send mail or create real authentication records.

Composer refresh was attempted before npm. The dry run proposed ten lock updates, comprising six Artisan Toolbox development entries and four compatible transitive updates. Its separate install plan proposed six updates, comprising those four transitive dependencies plus two local development aliases. The existing lock was preserved rather than replacing stable package selections with workspace aliases. The npm compatibility dry run reported the same resolved runtime/test versions. Canonical file:vendor frontend installs refreshed local copies. Incremental same-version installation, including force, initially left stale sources. Only the generated package directory was recreated through npm after validating that it was not a symlink. A recursive source comparison and Vite restart verified the final copy. No source alias, copied implementation inside the app, forced version or credential disclosure was used.

The consumer skill was updated for public bindings, errors, named models, canonical guide destinations and the presentation boundary. Boost list-skills discovers it in the real docs consumer. Manual matching review selects it for adding Inertia field errors to a Front Awesome Vue control; it does not apply to an unrelated database-index request. No consumer generated skill copies were independently edited.
